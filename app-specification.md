9) To-Do List веб-приложение (планировщик задач) — спецификация
1. Что такое спецификация?
Спецификация — это документ, который подробно объясняет проект.

Она нужна для того, чтобы было понятно:

что должно уметь приложение
как оно работает
какие разделы есть в системе
какие функции уже реализованы
какие функции можно добавить позже
Если совсем просто: спецификация = подробный план проекта.

2. Название проекта
Планировщик задач

Также проект можно назвать:

To-Do List
Task Manager
3. Цель проекта
Создать удобное веб-приложение для управления задачами.

Пользователь должен иметь возможность:

записывать задачи
указывать важность задачи
ставить дедлайн
распределять задачи по проектам
видеть задачи на сегодня
хранить выполненные задачи в архиве
4. Тип приложения
Это веб-приложение.

То есть программа работает в браузере и не требует отдельной установки как обычное настольное приложение.

10. Описание разделов
Входящие
Это основной раздел для работы с задачами.

Здесь пользователь может:

добавить новую задачу
увидеть список всех активных задач
удалить задачу
отметить задачу выполненной
Сегодня
Показывает задачи, у которых дедлайн установлен на сегодняшнюю дату.

Этот раздел нужен для того, чтобы пользователь сразу видел самые актуальные дела.

Планы
Показывает задачи, у которых дедлайн установлен на будущую дату.

Этот раздел нужен для долгосрочного планирования.

Календарь
Показывает задачи, сгруппированные по датам.

Это позволяет увидеть нагрузку по дням.

Проекты
Показывает задачи, сгруппированные по тегам.

Например:

Учёба
Работа
Личное
Архив
Показывает все выполненные задачи.

Этот раздел нужен для хранения завершённых дел.

12. Структура одной задачи
Каждая задача в системе содержит:

id — уникальный номер задачи
text — текст задачи
priority — приоритет
deadline — дата выполнения
tag — тег или проект
completed — выполнена задача или нет
createdAt — дата создания
13. Приоритеты задач
В текущей версии используются 3 уровня приоритета:

Низкий
Средний
Высокий
Каждый приоритет отображается своим цветом.

14. Логика работы приложения
При добавлении задачи:
Пользователь вводит текст
Выбирает приоритет
При необходимости указывает дату
При необходимости пишет тег
Нажимает кнопку Добавить
Задача сохраняется
Задача появляется в списке
При нажатии на ✓:
Задача отмечается выполненной
Она исчезает из активных разделов
Она попадает в раздел Архив
При удалении задачи:
Задача полностью удаляется из системы
15. Сохранение данных
В проекте используются два способа хранения данных.

localStorage
Это локальная память браузера.

Она нужна для того, чтобы задачи не исчезали после обновления страницы.

JSONBin
Это облачное хранилище данных.

Оно используется для сохранения задач в интернете.

Если облачное хранилище временно недоступно, приложение может использовать локальное сохранение.
